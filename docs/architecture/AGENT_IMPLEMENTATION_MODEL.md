# SwissEdge Agent Implementation Model

Date: 2026-06-08

## Purpose

This document defines the distinction between current SwissEdge agent personas, deterministic governance workers, future LLM-assisted agents, and future Claude-powered tool-using agents.

It prevents SwissEdge from overstating current runtime capability. Current SwissEdge agents are documented personas and deterministic/read-only governance workers. They are not yet live Claude or LLM agents.

## Current Implementation Model

Fontana and Dani Weber are currently exposed through FastAPI endpoints. These endpoints query backend services and database state, derive structured diagnostics, and return deterministic reports.

Current implementation characteristics:

- Reports are generated by backend code, not LLM reasoning.
- Agent outputs are structured and deterministic for the same available data.
- Existing endpoints remain read-only diagnostics unless explicitly approved otherwise.
- No Claude tool use is active.
- No LLM is currently reasoning over backend data.
- Agent documents define personas, missions, skills, permissions, and guardrails, but they are not yet used as live system prompts.

## What Current Agents Are

Current SwissEdge agents are:

- Officially documented personas with missions, responsibilities, room assignments, permissions, and guardrails.
- Deterministic diagnostic workers when backed by backend services and endpoints.
- Read-only governance surfaces that summarize system state, bottlenecks, risks, and proposed improvements.
- Product and architecture contracts for how future live agents should behave.

## What Current Agents Are Not

Current SwissEdge agents are not:

- Live Claude agents.
- Live ChatGPT agents.
- Autonomous LLM agents.
- Tool-using agents with write permissions.
- Runtime consumers of `docs/agents/*.md` as system prompts.
- Investment recommendation engines.
- Auto-fix, auto-apply, auto-discard, or auto-publish systems.

## Agent Model Types

| Type | Definition | Current SwissEdge status |
| --- | --- | --- |
| Agent persona | A documented role, mission, skills, permissions, tone, and guardrail profile. | Exists in `docs/agents/*.md`. |
| Deterministic diagnostic worker | Backend code that reads approved data sources and returns structured diagnostics without LLM reasoning. | Exists for Fontana and Dani Weber surfaces. |
| LLM-assisted agent | An LLM layer that reasons over read-only backend context and official agent documents, while keeping deterministic fallback. | Future candidate only. |
| Claude-powered tool-using agent | A Claude agent that can use tools against SwissEdge context and possibly perform approved actions. | Not approved and not implemented. |

## Why MVP Starts With Deterministic Agents

SwissEdge MVP starts with deterministic agents because Dani needs reliable governance before autonomous reasoning.

Deterministic agents provide:

- Repeatable reports.
- Easier debugging.
- Safer read-only behavior.
- Clear endpoint contracts.
- Lower hallucination risk.
- A stable baseline for future LLM comparison.
- No hidden reasoning layer between source data and UI output.

This protects the product guardrail that SwissEdge must not present invented, unmapped, or unverified guidance as real operational truth.

## Future System Prompt Path

Existing agent documents can become future prompt foundations, but only after an approved sprint defines the runtime contract.

Future prompt sources may include:

- `docs/agents/FONTANA.md`
- `docs/agents/DANI_WEBER.md`
- `docs/agents/README.md`
- `docs/governance/AGENT_MODEL.md`
- `docs/governance/GUARDRAILS.md`
- `docs/engineering/DEFINITION_OF_DONE.md`

Before use as system prompts, the documents must be reviewed for:

- Runtime-safe wording.
- Explicit forbidden actions.
- Required refusal behavior.
- Source hierarchy.
- Human approval checkpoints.
- Deterministic fallback behavior.
- No investment recommendation language.

## Future Path To Real Claude Agents

A future Claude-assisted implementation may:

- Use deterministic endpoints as read-only data providers.
- Build prompt context from official agent documents.
- Ask Claude to produce findings, diagnostics, and improvement proposals.
- Store or display LLM-assisted reports with clear labeling.
- Compare LLM-assisted output against deterministic diagnostics.
- Require human approval before any write, publish, discard, scanner, cron, or operational change.

This path must be implemented incrementally and must never replace deterministic governance foundations without explicit approval.

## Required Guardrails Before Enabling LLM Agents

Before enabling any LLM-assisted or Claude-powered agent, SwissEdge requires:

- Explicit Dani approval.
- Product/architecture approval from ChatGPT.
- Updated guardrails in `docs/governance/GUARDRAILS.md`.
- Clear source-of-truth hierarchy.
- Prompt and context-pack review.
- No secrets in prompts or generated packs.
- Read-only data access by default.
- No investment recommendation language.
- No buy/sell language.
- No auto-trading.
- No auto-publish.
- No auto-discard.
- No scanner, cron, or live-AI changes without explicit approval.
- Labels that distinguish deterministic output from LLM-assisted output.
- Verification by Codex and Claude Code before use.

## Human Approval Requirement

Human approval is mandatory before any LLM-assisted agent output can:

- Change persisted business state.
- Publish externally.
- Discard or promote cases.
- Change scanner or cron behavior.
- Claim final operational authority.
- Present investment conclusions as advice.

Dani remains the final decision maker. LLM agents may propose, summarize, or diagnose only inside approved boundaries.

## Deterministic Fallback Requirement

Any future LLM-assisted agent must preserve deterministic fallback.

Fallback must allow SwissEdge to:

- Continue showing read-only governance diagnostics when LLM access is unavailable.
- Compare LLM findings against deterministic reports.
- Mark LLM output unavailable without blocking core product workflows.
- Avoid fabricating results when context is incomplete.
- Keep official backend endpoint behavior stable.
