# SwissEdge AI Collaboration Model

## Purpose

This document defines how Dani, ChatGPT, Claude, Codex, and Claude Code collaborate inside SwissEdge. It keeps product decisions, UX work, implementation, verification, and documentation updates coordinated under the official SwissEdge guardrails.

## Roles

### Dani

Dani is the Product Owner, final decision maker, and repository owner. Dani provides product direction, priorities, screenshots, runtime validation, final acceptance, and approval for product and architecture decisions.

### ChatGPT

ChatGPT is the Product Architect / PM / Governance Designer. ChatGPT defines product behavior, architecture decisions, sprint prompts, guardrails, and reviews outputs from Codex and Claude when product or governance implications exist.

### Claude

Claude is the UX Engineer without repository access. Claude works from screenshots, screenshot URLs, `docs/product/PRD.md`, `docs/product/MVP_SCOPE.md`, `docs/governance/GUARDRAILS.md`, `docs/ux/SCREENSHOT_MAP.md`, and specific UX task briefs. Claude must not invent backend behavior, product rules, persisted state, or runtime capabilities.

### Codex

Codex is the Implementation Engineer with repository access. Codex implements approved tasks, updates code or docs as scoped, respects guardrails, verifies the smallest meaningful checks, and reports files changed plus verification performed.

### Claude Code

Claude Code is the Verification Engineer with repository access. Claude Code verifies implementation, builds, tests, wiring, guardrails, and regression risk. Claude Code must follow `CLAUDE.md`.

## Standard Workflow

1. Dani request.
2. ChatGPT product/architecture review.
3. Claude UX task if needed.
4. ChatGPT review of UX if architecture or product implications exist.
5. Codex implementation.
6. Claude Code verification.
7. Dani approval.
8. Documentation and context packs updated.

## Context Packs

Generated context packs live under `entrega/`:

- `entrega/chatgpt`: product, governance, architecture, agent, and sprint context for ChatGPT.
- `entrega/codex`: implementation context for Codex.
- `entrega/claude`: UX and product context for Claude.
- `entrega/claude-code`: verification context for Claude Code.

Context packs are generated by `scripts/context_delivery/build_context_pack.py`. They are handoff aids only; official source-of-truth documents remain the files listed in `docs/DOCUMENT_VERSION_INDEX.md`.

## Claude UX Screenshot Protocol

Claude UX tasks require:

- Exact local URL.
- Screenshots.
- Target state.
- Viewport.
- What Claude may change.
- What Claude must not change.
- Expected Codex handoff.

Claude must work from the supplied screenshot context and official docs. If the screenshot or task brief does not establish a backend behavior, Claude must mark it UNKNOWN rather than inventing it.

## Guardrails

All collaborators must follow:

- `docs/governance/GUARDRAILS.md`
- `CLAUDE.md`
- `docs/engineering/DEFINITION_OF_DONE.md`

Non-negotiable rules:

- No auto-trading.
- No investment recommendation language.
- No auto-publish.
- No auto-discard.
- No scanner changes without approval.
- No cron changes without approval.
- No live-AI changes without approval.
- No fake data presented as real.
- No product or architecture invention when context is missing.

## Handoff Expectations

### ChatGPT To Codex

- Goal.
- Context.
- In-scope tasks.
- Out-of-scope items.
- Guardrails.
- Acceptance criteria.
- Required verification.
- Expected final report.

### ChatGPT To Claude

- Exact route or screenshot URL.
- Screenshots or screenshot requirements.
- Product goal.
- UX questions.
- What may change.
- What must not change.
- Relevant official docs.
- Expected Codex handoff if implementation is needed.

### Claude To Codex

- UX findings.
- Recommended changes.
- Screenshots referenced.
- Layout or interaction constraints.
- Product assumptions marked explicitly.
- Unknowns that require ChatGPT or Dani.

### Codex To Claude Code

- Files changed.
- Behavior changed.
- Guardrails checked.
- Tests or commands run.
- Known risks.
- Deferred work.

### Claude Code To Dani / ChatGPT

- Findings first, ordered by severity.
- File and line references when possible.
- Checks run.
- Residual risk.
- Verdict: GO, NO-GO, or GO with caveats.

## Failure Mode

If any AI lacks context or detects a conflict:

- Stop.
- Mark the state as UNKNOWN.
- Ask Dani or ChatGPT.
- Do not invent missing facts, backend behavior, product rules, data state, or approval.
